## 场景

已经有一个可以对DSL做语法(syntax)和语义(semantic)校验的springboot的服务器了并且在服务器端实现了LSP(Language Server Protocol)，这个LSP的目的是对接Web IDE的请求。
现在想基于这些能力扩展一个CLI工具用于Claude Code的Skill，让这个Skill在生成DSL以后用这个CLI做语法和语义的校验。

## 尝试

在Claude Code里输入下面的提示词：

> Generate a cli tool for syntax and semantic validation of DSL, that need support to be used by LLM, the tool's name is "xpower-eam", use the tool like "xpower-eam validation --input file.dsl --format json". Support JSON output format to help LLM understand the output. Please also generate tool interface (schema) for LLM.

上面的提示词不论是用Claude Sonnet 4.5还是GLM 4.7都有不足：

### Claude Sonnet 4.5

Claude帮助生成了一个基于`org.springframework.boot.CommandLineRunner`的命令行工具，这种实现方法的问题是启动命令行工具需要启动springboot的服务器，耗时不说，springboot的服务器启动会在命令行交互界面写出大量本不属于CLI需要输出的信息，消耗大量的token。

### GLM 4.7

GLM首选了用Java J2SE生成命令行工具，命令行的输出是个很简洁的JSON，这个方向是对的，但是由于原始的语法和语义校验的能力是在springboot服务器里实现的，有大量的spring DI的依赖。J2SE无法完成对Spring DI的梳理和去除，最后自己编写了个简单的语义校验草草了事。

## 根因

在上面的AI实现中并没有发现LLM在能力上的重要分别，倒是暴露了提示词的信息不足造成AI无法准确的完成工作。后调整提示词为：

> Generate a cli tool for syntax and semantic validation of DSL, that need support to be used by LLM, the tool's name is "xpower-eam", use the tool like "xpower-eam validation --input file.dsl --format json". Support JSON output format to help LLM understand the output. Please also generate tool interface (schema) for LLM. This CLI should call EAM server LSP for the syntax and semantic validation instead of a whole wrapper of backend classes.

使用下面的提示词，不论是Claude Sonnet 4.5还是GLM 4.7都可以近乎完美的完成工作，并且有意思的是两个LLM都使用了Python实现了这个CLI工具

## 一句话总结

在LLM差不多的情况下，提示词对结果的影响远大于模型对结果的影响。向让工作做的完美，人对现有工程的理解很重要，毕竟token还很贵，LLM的上下文有限，你不能把一个项目所有的代码都喂给LLM。
